ความสอดคล้องตามเกณฑ์ประเมิน

ตารางตรวจสอบเกณฑ์ขั้นต่ำ 6 ข้อของรายวิชา (14 คะแนน)

สรุปความสมบูรณ์ของฟีเจอร์ตามเกณฑ์ที่อาจารย์กำหนด ครบถ้วน 100% พร้อมตอบคำถามได้อย่างมั่นใจ

ข้อ เกณฑ์ข้อกำหนดของอาจารย์ ฟังก์ชันและการทำงานจริงในระบบของเรา ผลการประเมิน
1 สมัครสมาชิกและเข้าสู่ระบบ
(Password Hashing ที่เหมาะสม)		 ใช้ Bcrypt Cost Factor 10 (Salt 10 Rounds) เข้ารหัสก่อนบันทึกลง Store ไม่มี Plaintext พร้อมระบบ 2FA OTP ส่งตรงเข้า Gmail จริง ✅ ผ่าน (เกินเกณฑ์)
2 ผู้ใช้อย่างน้อย 2 บทบาท
(User และ Admin สิทธิ์ต่างกันชัดเจน)		 แยกสิทธิ์ด้วย RBAC Middleware โดย User จอง/ยืม/ดูเฉพาะรายการตนเอง ส่วน Admin อนุมัติ/ปฏิเสธ, เพิ่มห้อง/อุปกรณ์, ดูสถิติ และ Audit Log ✅ ผ่าน 100%
3 CRUD ที่ข้อมูลมี "เจ้าของ"
(User A แก้/ลบของ User B ไม่ได้)		 มี 2 ชุด (จองห้อง + ยืมอุปกรณ์) ทุกรายการผูก userId หาก User A ส่ง ID ของ User B มาแก้ไข เซิร์ฟเวอร์จะตอบ HTTP 403 Forbidden ทันที ✅ ผ่าน (กัน IDOR)
4 ฟอร์มรับข้อมูล อย่างน้อย 2 ฟอร์ม
(บันทึกฐานข้อมูลและแสดงผลกลับ)		 มี 3 ฟอร์ม: (1) ฟอร์มจองห้องแล็บ (2) ฟอร์มยืมอุปกรณ์ส่วนกลาง (3) ฟอร์มประเมินความพึงพอใจ 5 ดาว บันทึกลงฐานข้อมูลและแสดงในการ์ดทันที ✅ ผ่าน (มี 3 ฟอร์ม)
5 ข้อมูลส่วนบุคคลที่ต้องปิดบัง
(PII Masking เมื่อแสดงผล)		 ปิดบังข้อมูลตาม PDPA ครบ 4 ฟิลด์: เลขบัตร ปชช. (1100200****33), เบอร์โทร (081-***-5678), อีเมล, รหัสนักศึกษา พร้อมปุ่ม Toggle Unmask ✅ ผ่าน (เกินเกณฑ์)
6 หน้าผู้ดูแลระบบ อย่างน้อย 1 หน้า
(Admin Console)		 หน้า Admin Dashboard ครบวงจร: อนุมัติ/ปฏิเสธคำขอพร้อม Admin Note, เพิ่มห้อง/อุปกรณ์พร้อมอัปโหลดรูป, หน้ากราฟวิเคราะห์ข้อมูล และ Security Audit Trail ✅ ผ่าน 100%
ตรงตามแบบประเมินรายวิชาทุกข้อ พร้อมแสดงหลักฐานประกอบการให้คะแนน เกณฑ์ขั้นต่ำ 6 ข้อ ผ่านครบถ้วน

ใช้ทำอะไร: ศูนย์รวมประวัติคำขอทั้งหมดของผู้ใช้คนนั้น ตรวจสอบสถานะว่า "รออนุมัติ", "อนุมัติแล้ว" หรือ "ปฏิเสธ"
จุดเด่น: มีฟังก์ชัน แก้ไขวัตถุประสงค์ และ กดยกเลิกคำขอ ได้ด้วยตนเอง (CRUD Owner-based)

ผลลัพธ์: คำนวณคะแนนเฉลี่ยแบบถ่วงน้ำหนักและแสดงผลบนการ์ดสถิติหน้าแรกทันที

👁️ 5. ระบบคุ้มครองข้อมูลส่วนบุคคล (PDPA Masking)

ใช้ทำอะไร: ซ่อนเลขบัตรประชาชน เบอร์โทร และอีเมลบนหน้าจอ เพื่อป้องกันการแอบมอง (Shoulder Surfing)
ความปลอดภัย: หากผู้ใช้กดเปิดดูข้อมูลจริง (Toggle Unmask) ระบบจะบันทึก Audit Log พร้อม Timestamp ทันที

ใช้งานง่ายผ่านหน้าเว็บแบบ One-Stop Portal ไม่ต้องดาวน์โหลดแอปเพิ่มเติม ฟังก์ชันฝั่งนักศึกษาและอาจารย์

บทสรุป & เตรียมตอบคำถามอาจารย์

สรุปภาพรวมโครงงาน และแนวทางการตอบคำถาม (Q&A Ready)

คำถามยอดนิยมที่อาจารย์มักจะถามในการตรวจโปรเจกต์ พร้อมคำตอบเชิงเทคนิคที่ถูกต้อง 100%

❓ อาจารย์ถาม: "ระบบป้องกันไม่ให้ User A แอบลบข้อมูล User B ได้อย่างไร?"

💡 คำตอบ: "ระบบใช้ Server-Side Ownership Verification ครับ โดยใน API DELETE /api/bookings/:id เซิร์ฟเวอร์จะดึงข้อมูล record นั้นขึ้นมาตรวจสอบก่อนว่า record.userId === req.user.id หรือไม่ ถ้าไม่ตรงกัน ระบบจะบล็อกและตอบกลับ HTTP 403 Forbidden ทันที จึงป้องกันช่องโหว่ IDOR ได้ 100% ครับ"

❓ อาจารย์ถาม: "รหัสผ่านจัดเก็บอย่างไร มีความปลอดภัยแค่ไหน?"

💡 คำตอบ: "เราใช้ Bcrypt Hashing พร้อม Cost Factor 10 Rounds ครับ โดยระบบจะสุ่ม Salt ใหม่ทุกครั้งและทำการแฮชทางเดียว (One-Way Hashing) ก่อนบันทึกลงฐานข้อมูล ในระบบจะไม่มี Plaintext Password อยู่เลย แม้ฐานข้อมูลจะรั่วไหลออกไป ผู้โจมตีก็ไม่สามารถถอดรหัสผ่านได้ครับ"

❓ อาจารย์ถาม: "ข้อมูลส่วนบุคคลอะไรบ้างที่ทำการ Masking?"

💡 คำตอบ: "เรา Masking ครบ 4 ฟิลด์ครับ คือ เลขบัตรประชาชน (1100200****33), เบอร์โทร (081-***-5678), อีเมล และรหัสนักศึกษา ตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล (PDPA) และถ้าผู้ใช้กดเปิดดูข้อมูลจริง ระบบจะบันทึก Audit Log พร้อม Timestamp เพื่อความโปร่งใสครับ"
